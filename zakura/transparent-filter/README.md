# zakura-transparent-filter

Transparent PIR address filters, their validation and the wallet-side client; the `client` feature adds the blocking HTTP transport and `cli` the reference test-double binary. The library target keeps the name `transparent_filter`, so code moved from
wallet-pir's `transparent-filter` 0.1.0-rc.4 keeps its paths.

## transparent-filter

For current transparent script-history recovery and deployment, start at [wallet-pir's transparent PIR index](https://github.com/valargroup/wallet-pir/blob/main/transparent/docs/README.md). This document covers only the component named here.

BIP 158 transparent activity filters for Zcash: the `zcash-transparent-basic-v1`
application profile, a strict decoder, wallet-side matching, and the range
delivery envelope.

The handoff proposed the path `filters/transparent-activity`. This crate lives
at `zakura/transparent-filter` in wallet-libraries, alongside the other
Transparent protocol crates; production services stay in wallet-pir under
`transparent/services/`.

### What this does not claim

Filters let a wallet test its own scripts locally. They do not prove the server
built them honestly or completely. Matching a filter against the wallet's
accepted block hash binds *where* the filter claims to be, not *what* it
contains, so advancing coverage on a negative result is sound only if the
filter's author is trusted to have built it over the whole block.

There is no BIP 157 peer verification and no service signalling here.

### Validation

- `tests/bip158_vectors.rs` — the official BIP 158 basic-filter vectors, vendored
  in `tests/vectors/` with provenance in `SOURCE.md`.
- `tests/independent_crosscheck.rs` — filters generated by `btcsuite/btcd`'s
  `gcs` package, so expected and actual do not both come from this crate. See
  `tests/crosscheck/README.md` for pinned versions and regeneration. Go is not
  needed to run the Rust tests.
- `tests/golden_envelope.rs` — envelope bytes derived by hand from
  wallet-pir's `transparent/docs/filter-envelope.md`.

### Dependency note

The `zakura-gcs` crate supplies the shared codec extracted from rust-bitcoin
0.32.102. Production retains `bitcoin_hashes` and its I/O support, without the
Bitcoin transaction/address stack or its secp256k1 dependency. The exactly pinned
`bitcoin` crate remains a development-only byte and matching oracle.
