# transparent-filter

For current transparent script-history recovery and deployment, start at [the transparent PIR index](../../docs/README.md). This document covers only the component named here.

BIP 158 transparent activity filters for Zcash: the `zcash-transparent-basic-v1`
application profile, a strict decoder, wallet-side matching, and the range
delivery envelope.

The handoff proposed the path `filters/transparent-activity`. This crate lives
at `transparent/crates/transparent-filter`, alongside the other Transparent
protocol and wallet crates; production services live under
`transparent/services/`.

## What this does not claim

Filters let a wallet test its own scripts locally. They do not prove the server
built them honestly or completely. Matching a filter against the wallet's
accepted block hash binds *where* the filter claims to be, not *what* it
contains, so advancing coverage on a negative result is sound only if the
filter's author is trusted to have built it over the whole block.

There is no BIP 157 peer verification and no service signalling here.

## Validation

- `tests/bip158_vectors.rs` — the official BIP 158 basic-filter vectors, vendored
  in `tests/vectors/` with provenance in `SOURCE.md`.
- `tests/independent_crosscheck.rs` — filters generated by `btcsuite/btcd`'s
  `gcs` package, so expected and actual do not both come from this crate. See
  `tests/crosscheck/README.md` for pinned versions and regeneration. Go is not
  needed to run the Rust tests.
- `tests/golden_envelope.rs` — envelope bytes derived by hand from
  `transparent/docs/filter-envelope.md`.

## Dependency note

`bitcoin` is pinned exactly (`=0.32.102`) and used only for
`bip158::GcsFilterWriter` and `hashes::siphash24`. Its `std` feature pulls in
`secp256k1`, which this crate never uses; that weight matters for a mobile
build and is recorded as a follow-up rather than worked around here.
