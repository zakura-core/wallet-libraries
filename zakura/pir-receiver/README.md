# Receiver PIR

This crate provides bounded network steps for private receiver lookups. With the `wallet` feature, `publication`, `lookup` and `witness` connect a captured shard inventory to the SQLite wallet's recovery queue. The application owns networking and scheduling. No network future holds a database handle or lock.

## Wallet flow

1. Enable recovery for each account with `set_one_time_recovery_enabled`. Ordinary block sync continues independently.
2. Fetch the inventory head with `Inventories::head`, capture its chunks with `Inventories::capture`, and accept its end and activation coverage against a locally scanned block with `Inventory::accept` before opening an `InventoryClient`. Use one captured inventory per pass. Pass `publication` to `begin_one_time_recovery`. Choose whether sealed shards' filters may replace PIR; blind reads cost more queries and fewer downloads.
3. Choose rolling filters for a short gap when their measured download cost is lower. Match the returned batch against `one_time_receivers`, then atomically commit its block identities and positive keys with `record_one_time_filters`. A negative match makes no receiver query. An unavailable or pruned range is never a negative.
4. For direct catch-up, call `begin_one_time_recovery` with `direct = true`. It queues unfinished receives, funded unresolved refunds and existing obligations, without querying every old completed key.
5. Read bounded work with `one_time_recovery`. Call `lookup` outside the wallet lock, then commit with `record_one_time_lookup`. Each step covers sealed shards a validated filter excludes, then reads pages of at most one segment; every shard reaching the request's first unchecked height is required, including one that straddles it, and the recent tier is always read. Failures, including an expired captured session, use `defer_one_time_lookup`, never an empty result. `DirectoryError::Unsupported` from any step, including the head, capture and witness reads, is different: the service needs a newer client. Call `require_one_time_upgrade` and ask the user to update the app instead of deferring. Pending work is kept and resumes when a later `begin_one_time_recovery` accepts a publication this client captured. Recapture for a replacement inventory: a cursor from another inventory is never resumed, only progress through whole checked shards carries over.
6. For each witness request, call `witness` to read the payment's companion payload by its ordinal and pass the answer to `record_one_time_witness`. A request bound to another payment session returns `Revision`; call `refresh_one_time_witness`, which re-reads the payment under the current session instead of reinterpreting its ordinal. The wallet authenticates the note, rebuilds the rest of the path from its own tree, checks it against its own root, then checks spend coverage and records ordinary wallet ownership. A provisional payload is usable only at its exact construction block within the pruning depth; a final one at any later anchor. Unusable or missing witnesses leave the payment pending.

Seed recovery walks receive indexes until four consecutive complete empty histories from activation through a captured frontier. The birthday bounds credited history, not this walk: an authenticated pre-birthday payment marks its index used. A paid key resets the gap only after authentication and inclusion. New lookahead keys are queued through the already processed frontier in the same transaction. Receive issuance reuses the lowest unpaid eligible hole within the four-index window that payments mined on the wallet's chain justify. Refund identities come from authenticated funding memos or locally funded operations, not an index sweep. Recovering funding before the account birthday requires lowering that birthday and rescanning ordinary history.

`check_one_time_history` starts or resumes an explicit history check. An optional exclusive receive bound crosses the normal four-empty stopping point. `cancel_one_time_history` pauses that manual work without losing its cursor or independent positive hints. Repeated payments to completed keys outside retained filters require this manual check.

## Boundaries

Turning recovery off invalidates held callbacks and exposes no discovery work. It preserves existing notes, spending and reorg repair. There are no one-time-key scan watches, compact-block caches, aggregate filters, provider seen gates or restore passes. Targeted authentication of a PIR-returned payment remains necessary.

PIR hides the receiver within a query and the ordinal within a witness query. Query timing, count and which shards are read stay visible, so recovery reveals historical intervals, and a witness query reveals that a lookup found a candidate. This metadata privacy assumes an honest publisher. The service is trusted for complete indexing and honest negative answers. Wallet authentication and chain proofs prevent it from crediting an invented payment.

`tests/discovery.rs` uses the production snapshot, witness, shard filter and inventory builders and the encrypted PIR evaluator against a real SQLite wallet, including sealed and recent shards, multi-segment shards, substituted filters, replaced inventories and corrections. The service router and full application scheduling are tested in their owning repositories.
