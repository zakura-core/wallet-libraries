# zakura-transparent-private-server

The publisher's side of Transparent private mode:

- `filter`: building per-block and range activity filters, and experimental
  parent filters.
- `shard`: sealing shards by content, placing scripts in their directories,
  packing histories into page rows, choice tables, revision numbering, and the
  txid display tables, seals and split map.
- `native`: admitting and parsing uploads to a table, sizing its preprocessed
  segments, and the batched public hint.

The formats these produce, and the native profile each table uses, are
`zakura-transparent-private-shared`'s. Wallet recovery is in
`zakura-transparent-private-wallet`, which this crate never depends on. Running
services, ingesting chain data and storing publications stay with their
operators.

Feature `testing` adds `testing::service`, an in-process shard service over a
synthetic publication that evaluates real PIR, for wallet and application
tests. Never enable it in a production build.

`testdata/batched_hint_kat.json` is generated by the independent Python oracle
`testdata/batched_hint_kat.py`; the unit test `known_answer_vectors` checks the
batched hint against it. `tests/crosscheck/` holds filters generated by
`btcsuite/btcd`'s `gcs` package; see its README.
